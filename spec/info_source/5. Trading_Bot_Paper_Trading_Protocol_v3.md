# **1. Account Parameters — The Stress Test Design**

|  |
| --- |
| **IN PLAIN ENGLISH**  Here is the most important thing to understand about this version of the programme: we are deliberately testing position sizes that would be considered aggressive. The reason is simple — paper trading is the only safe place to do it.  At 75% position sizing, a single bad trade can take a significant chunk out of the pot. A losing streak could produce a 20-30% drawdown. We want to see that happen on paper. We want to understand how quickly the bot recovers, whether the stop loss system holds, and whether the Gate system prevents the worst outcomes.  What we learn from the 75% account during paper trading becomes the evidence base for our decision about when and whether to use 75% sizing with real money. The data makes that decision — not optimism.  All three accounts use identical signals — same stocks, same entry criteria, same exits. Position size is the only variable. This gives us a clean, direct comparison of what each sizing level produces in terms of both returns and drawdowns across the same market conditions. |

# **2. Daily Data Collection — Recording Every Trade**

|  |
| --- |
| **IN PLAIN ENGLISH**  Every single trade across all three accounts gets recorded in full. No exceptions, no shortcuts.  The daily data is the bot's diary. The pre-trade section captures what the bot and the 5-gate system saw before entering. The post-trade section records what actually happened. Together they form the complete picture that teaches the bot what works, what does not, and what outside events can hijack an otherwise perfect setup.  There is now a third section in the daily log that did not exist in version 2 — the Gate Audit Trail. Every trade the bot considers gets logged through all five gates, even the ones that get rejected. This tells us whether our threat detection is calibrated correctly or whether it is blocking too many good trades or letting bad ones through.  And every loss now gets a category label — A, B, C, or D — so we can separate the losses that happened because our strategy was wrong from the losses that happened because an outside event hijacked us. Those are very different problems requiring very different solutions. |

# **5. Loss Categorisation & Exogenous Shock Memory**

|  |
| --- |
| **IN PLAIN ENGLISH**  This is one of the most important additions in version 3 — and the one that came directly from recognising that the outside world can hijack even a perfect trade setup.  Every loss gets a category label. Not to beat ourselves up about it — but because different types of losses require completely different responses. A strategy failure means we need to tune the signals. An exogenous shock means we need to add a new rule to Gate 1. An execution issue means we need to fix the timing. A contradiction miss means Gate 4 needs a better prompt.  The exogenous shock memory database is how the bot learns to see danger coming from outside the charts. Every time an outside event causes a loss, we log it in detail. Over 6 months that database becomes the bot's instinct for danger — patterns emerge, new rules get written, and Gate 1 gets smarter with every single exogenous event we document. |

## **5.1 Loss Categories — Label Every Loss**

|  |  |  |  |
| --- | --- | --- | --- |
| **LABEL** | **CATEGORY** | **DEFINITION** | **WHAT IT MEANS FOR THE BOT** |
| **A** | **Strategy Failure** | Our signal was wrong. The technical or sentiment read failed and the trade lost on its own merits. | Tune signals. Adjust entry criteria. Review Gate 3 confidence threshold. |
| **B** | **Exogenous Shock** | An outside event hijacked an otherwise valid setup — macro surprise, geopolitical event, sector contagion, short seller attack. | Log in threat memory database. Run post-loss Claude review. Candidate for new Gate 1 rule. |
| **C** | **Execution Issue** | Signal was right but timing, slippage, overnight gap, or pre-market move caused the loss. | Review Gate 1 pre-market gap check. Adjust entry timing rules. |
| **D** | **Contradiction Missed** | Gate 4 should have flagged a conflict between the signal and market context but did not. | Review Gate 4 prompt. Add the missed contradiction type to the prompt explicitly. |

# **7. Drawdown Framework — Paper vs Live**

|  |
| --- |
| **IN PLAIN ENGLISH**  This is one of the most important conceptual differences in version 3. Paper trading and live trading have deliberately different drawdown rules — and the reason is that we want to learn as much as possible from paper trading before we set the live guardrails.  With fake money we let the bot run into uncomfortable territory on purpose. We do not stop it when Account 3 drops 20% — we watch exactly what happens. Does the Gate system eventually prevent further damage? How long does recovery take? What caused the drawdown — strategy failures, exogenous shocks, or bad luck? All of that is data we cannot get if we pull the plug too early.  With real money the guardrails are tight. The bot auto-pauses at 8% drawdown. A human reviews before it resumes. If it hits 15% the bot stops completely and does not restart without a full review and agreed plan.  You cannot be surprised by a 15% drawdown in live trading if you have already watched it happen three times in paper trading. That is the entire point. |

|  |  |  |  |
| --- | --- | --- | --- |
| **DRAWDOWN LEVEL** | **PAPER TRADING** | **LIVE TRADING** | **PURPOSE** |
| 5% from peak | Log and monitor only | Warning flag — increase logging | Early alert — is this a pattern? |
| 8% from peak | Log — do NOT stop. Learn from it. | Bot auto-pauses. Human review required. | Real money needs tighter leash |
| 15% from peak | Log — do NOT stop. This is the stress test. | Full stop. No restart without agreed plan. | Absolute risk limit on real money |
| 20%+ from peak | Log everything. Maximum learning value. | Never reached — 15% is the kill switch. | Paper only — understand the worst case |

|  |
| --- |
| **THE PHILOSOPHY**  Paper trading isn't real money — so we push it. We want to see the scary scenarios play out on paper so they hold no surprises when real money is at stake. A 25% drawdown on Account 3 during paper trading is not a failure — it is the most valuable data point in the entire programme. |

# **8. Go-Live Criteria — Earning the Right to Real Money**

|  |
| --- |
| **IN PLAIN ENGLISH**  Every single criterion below must be met before one dollar of real money is deployed. Not most of them — all of them. Simultaneously.  These criteria exist because each one represents a specific risk that has destroyed real trading accounts. The Brier score measures whether the bot's win probability predictions are actually calibrated — a bot that says 70% win probability on every trade but only wins 55% of the time has a calibration problem that will cost money at scale. The Sharpe ratio measures whether returns are consistent or lumpy — a bot that made all its money in one lucky week is not ready for live trading.  The go-live position size is 33%. Not 50%. Not 75%. The bot earns the right to scale position size through live performance data — not paper trading optimism.  Think of this section as the exam at the end of six months of study. You do not sit the exam early because you feel ready. You sit it when the data says you are ready. |

|  |
| --- |
| **NON-NEGOTIABLE**  All criteria must be met simultaneously. If 11 out of 12 are green and one is red — the bot is not ready. No exceptions. No shortcuts. |
