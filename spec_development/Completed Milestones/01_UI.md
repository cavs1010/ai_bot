# 🎯 Milestone

## Name

Watchlist Generation & Dry-Run Pipeline Execution with Real-Time Funnel Telemetry

## Expected Outcome

> The user can generate an updated universe watchlist dynamically via a "Load Watchlist" button and run the full dry-run trading intelligence pipeline via a "Run Pipeline (Dry Run)" button. Both the "Nightly Filter Funnel Summary" metrics and the "Nightly Candidate Process List" table update dynamically in the Web UI based on the output of the pipeline run (reflecting Universe Watchlist -> Scanned Candidates -> Gate 1 Hard Limits -> Gate 5 BUY Signals -> Risk Approval), without placing live orders (`PLACE_ORDERS=false`).

## Completion Criteria

The milestone is completed when:

- [x] The user can trigger the creation/update of the stock universe watchlist from the Web UI.
- [x] The user can trigger the full dry-run trading intelligence pipeline from the Web UI.
- [x] The "Nightly Filter Funnel Summary" dashboard section dynamically updates its 6 funnel stages (Universe Watchlist, Scanned Candidate, Processed Gate 1, Gate-5 BUY Signal, Risk Approved, Orders Placed) upon running the pipeline.
- [x] The "Nightly Candidate Process List" table dynamically updates to reflect real-time ticker decisions, gate statuses, sentiment, edge, win probability, trade geometry, risk sizing, and audit notes.
- [x] Order placement remains simulated/disabled (`PLACE_ORDERS=false`) for security.

# 🚧 Blockers & Enabling Milestones

> Use this when the current Milestone becomes blocked or unnecessarily expensive to continue without completing another piece of work first.

## Current Blocker

**Problem:**  
Iterative UI testing, visual state verification, and error-handling verification require triggering the full live trading intelligence pipeline, which makes repeated API calls to LLM services (Gemini/Claude) and external market data providers.

**Impact:**  
- Burns unnecessary LLM API tokens and credits during simple UI layout, badge, and table tweaks.
- Extremely slow feedback loop (minutes per run) for testing UI state handling and animations.
- Stale UI states on page refresh because pipeline run execution results are not saved anywhere.

**Can I reasonably continue without solving it?**  
No — testing and polishing the current milestone's UI is unnecessarily expensive and slow without a local caching and zero-cost simulation/replay mechanism.

## Enabling Solution (Minimum Enabling Scope)

**Status:** ✅ Completed

1. **Auto-Save Last Pipeline Run (`latest_run.json`)**:
   - Persists the full structured telemetry JSON payload to disk.
2. **Persistent State on Reload (`/api/pipeline/last-run` / `/api/run/latest`)**:
   - On page load/refresh, restores the last execution's funnel metrics and candidate table without needing a new execution.
3. **Zero-Cost Fast Replay / Simulation Mode (`/api/pipeline/replay`)**:
   - Added a "Fast Replay ($0 Tokens)" button in the UI that streams saved/simulated execution telemetry over SSE with ~200-300ms step intervals.
   - Allows instant, $0-cost visual verification of the 6-stage funnel summary, candidate card transitions, and gate status tags.
